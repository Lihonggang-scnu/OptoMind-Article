## 建议的分批顺序（先本地、后付费）

1. **B0：零模型费接线批（E01–E04，先做）**。只使用当前 Article/VeriTMM 合成入口和 hand-selected probe；冻结一个 mechanism pair、噪声、成本、holdout 和失败类别。先验证：候选是否真正生成、每个竞争解释是否重新拟合、prediction commit 是否先于 acquisition、derived view 是否不增加独立 likelihood。若 E01 没有自动前端候选，E01/E02 不进入目标宣称；保留为未实现/证据不足。
2. **B1：资产与迁移批（E05–E07）**。不调用模型：一条合成轨迹→一个 ProgramAsset→5 次干净回放→5 个未见任务；随后固定库 C 与同库受限演化 D 做相同 T/V/P/A。只要发现答案硬编码、任务重写或库/预算变化，就停止并记录缺口，不用“反思”补称 RSI。
3. **B2：Review 消费批（E08）**。优先用已有本地 snapshot/replay；做三个问题和一个有/无关键 claim 的消融。缺原文锚点、source hash 或 request binding 时立即停，不能用旧全文回放冒充新检索能力，也不在本核对中开 API。若确需真实 Review 调用，按现有 60 元复核账本和剩余 `72.2719072` 元逐项预留，单项先小额、先看 receipt，再决定下一项。
4. **B3：后端/器件批（E09–E10）**。先做 5 个固定 backend pair 的同评价器比较，再对已有候选做 450–700 nm/51 点独立重算和小样本容差；费用为本地计算优先。E10 的当前 `0.0353624` 先按“目标未达”保留，不能用更换网格、代理损失或候选拼接洗成通过。
5. **B4：一条连续案例（E11）**。只有 B0–B2 的链条有可追溯素材后再做；合成来源、手选结构和没有制造的结果必须在 case manifest 中显式标记。不要把多次最优运行拼成连续成功。

## 达标/未实现/证据不足记录要求

每项产物至少绑定：输入规格、代码/配置版本、case/run identity、原始 CSV/JSON、候选和未选原因、预测 commit 与观测顺序、独立评价器、预算/实际成本、人工介入和结论状态。`达标`只对冻结门槛和独立证据生效；`目标未达`保留实际数字；`未实现`列出缺失合同；`证据不足`列出需要的最小留出/成对/消融素材。纯计算探针统一写 `synthetic`/`hand-selected`，不得改名为自主、真实或制造成功。
